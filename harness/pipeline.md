# Glowlog 디자인 하네스 — 파이프라인

> 출처: R3 인터뷰 (2026-10-10)
> 목적·완료 기준: `harness/purpose.md` / 원래 작업 흐름: `story-work.md`
> 수치 원본: `harness/rules.json` — 이 문서의 표와 다르면 rules.json이 우선한다.

## 단계

| 단계 | 대응 문장 (story-work) | 입력 | 출력 | 게이트 위치 |
|---|---|---|---|---|
| S1 레퍼런스 | 1·2 | 화면 번호, 키워드 1~3개 | 레퍼런스 분석 문서 (레퍼런스 3개 이상) | G1 |
| S2 설계 | 3 | S1 분석 문서, PRD 해당 화면 절 | 화면 설계 문서 | G2 |
| S3 키스크린 | 4·5 | S2 설계 문서, `design.md` | 컨셉 시안 HTML 2개 (390×844, 외부 참조 없는 단독 파일 — Figma 가져오기용) | G3 |
| (사람 승인) | 5 | 시안 2개, `design.md` 👀 체크리스트 | `03-choice.md` (`choose.py`가 기록) | CHOICE |
| S4 컴포넌트·화면 | 6 | 선택된 시안 1개, `design.md`, 공용 컴포넌트 파일 | 공용 컴포넌트 파일(추가분), 최종 화면 HTML | G4 |
| S5 판정 | 7 | 최종 화면 HTML, 실행 폴더 전체(이력·스냅샷·선택) | `05-report.json` | S5 |

- 게이트 통과 조건: `harness/gates.md`
- S3 → S4 사이에서 본인이 시안 2개 중 1개를 고른다 (유일한 사람 승인 지점, CHOICE 게이트).

## 공용 컴포넌트 규칙

- 공용 컴포넌트 파일은 1개만 두고, 실행이 거듭돼도 유지한다.
- 실행마다 **추가만 허용**한다. 기존 클래스는 수정하거나 삭제하지 않는다.
- 판정: 이전 실행보다 클래스 수가 줄었거나, 같은 이름의 정의가 바뀌었으면 위반이다.

## 되돌아가는 지점

실패 시 복귀 지점·최대 횟수는 `harness/gates.md` "실패 시 복귀" 표를 단일 기준으로 한다.
