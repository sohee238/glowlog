# Glowlog 디자인 하네스 — 목적

> 출처: R2 인터뷰 (2026-10-10)
> 서비스 기준: `story-service.md` / 작업 흐름: `story-work.md`

## 매번 달라지는 입력

| 입력 | 형식 | 제약 |
|---|---|---|
| 대상 화면 번호 | 정수 | 1, 2, 3 중 1개 |
| uibowl 검색 키워드 | 문자열 | 1~3개 |

그 밖의 `PRD.md`, `design.md`, `CLAUDE.md`는 고정값이며 하네스 실행 중에 수정하지 않는다.

## 사용자

| 역할 | 누구 |
|---|---|
| 실행자 | 본인 (1명) |
| 결과물 수신자 | 다음 단계 AI 에이전트 |

→ 결과물은 사람 눈으로 보기 위한 것이 아니라 에이전트가 읽을 수 있어야 한다.
  (PRD: "AI 에이전트가 읽고 이어서 작업할 수 있는 데이터로서의 디자인")

## 결과물 형태

1. **주 산출물:** `screens/screen-{번호}.html` — 390×844, 판정 스크립트 검증 대상
2. **기계 판독 표시:** 색·radius·font-size를 사용한 요소에는 사용한 토큰 이름을 `data-token` 속성으로 반드시 표시한다 (예: `data-token="bg/card"`). 판정 규칙은 `harness/gates.md`.

## 범위 밖

- **Figma 이관:** 하네스는 HTML 승인에서 끝난다. Figma로 옮기는 작업은 하네스 밖에서 본인이 수동으로 한다.

## 완료 기준 (한 문장)

대상 화면 HTML 1개가 `harness/gates.md` S5 조건을 모두 만족하고(판정 스크립트 위반 0건),
사람 승인(시안 선택) 1회를 받으면 완료.
(위반 종류 목록은 `harness/gates.md`에만 둔다 — 규칙이 늘어도 이 문장은 고치지 않는다.)
